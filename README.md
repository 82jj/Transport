# Transport — four independent deployable projects

## الفصل الفعلي (0.3.0)

هذا المستودع يحتفظ بأربعة مشاريع مستقلة تمامًا في البناء والتشغيل، وليس تطبيقًا يغيّر واجهته بـ `APP_MODE`:

| المشروع | مجلد البناء الوحيد | رابط الواجهة |
| --- | --- | --- |
| المستخدم | `apps/user` | https://transport-user-isolated-production.up.railway.app |
| الكابتن | `apps/captain` | https://transport-captain-isolated-production.up.railway.app |
| لوحة الإدارة | `apps/admin` | https://transport-admin-isolated-production.up.railway.app |
| API | `apps/api` | خدمة خلفية فقط، بدون واجهات |

لكل مشروع package.json وDockerfile وملفات تشغيل خاصة. لا تُنسخ ملفات أي واجهة أخرى إلى صورة Docker. يمكن نقل أي مجلد إلى مستودع مستقل دون تغيير كوده؛ بقاؤها في مستودع واحد لإدارة الإصدارات فقط. تنقل الواجهات طلبات API المسموحة إلى الخدمة الخلفية نفسها عبر الشبكة الداخلية، ولا تتصل بروابط بعضها ولا تحتوي أزرارًا للتبديل بينها. `APP_MODE` مهمل وغير مستخدم. ملف التشغيل في جذر المستودع يعيد 410 بدل الواجهة الجامعة القديمة.

## الإعداد

في Railway عيّن Root Directory لكل خدمة إلى `/apps/user` أو `/apps/captain` أو `/apps/admin` أو `/apps/api`. ملف إعداد Railway مساره مطلق من جذر المستودع مثل `/apps/user/railway.json`. أمر البدء `node server.js` وفحص الصحة `/healthz`.

الواجهات تحتاج `API_ORIGIN` يشير إلى عنوان خدمة API الداخلية مع المنفذ، و`PUBLIC_ORIGIN` يساوي رابط الواجهة نفسها. لا توجد عناوين الكابتن أو الإدارة داخل تطبيق المستخدم. API يحتاج `DATA_DIR=/data` على Volume دائم؛ البيانات والحسابات والجلسات تحفظ في SQLite، وليس مصفوفة مستقلة داخل كل واجهة. لا يفتح API صفحات HTML ولا ملفات الواجهات.

تهيئة أول حساب إدارة تكون بمتغيري `ADMIN_EMAIL` و`ADMIN_PASSWORD` (16 حرفًا على الأقل) في خدمة API فقط. لا توجد كلمة مرور افتراضية، ولا تسجيل إدارة عام. لا تضع كلمات المرور في المستودع. الحساب يُنشأ مرة واحدة؛ تعديل المتغير لا يعيد تعيين كلمة مرور حساب قائم. تسجيل المستخدم والكابتن منفصل، والكابتن ينتظر موافقة الإدارة. الكوكيز خاصة بالنطاق وبالدور، HttpOnly وSameSite=Strict وSecure في الإنتاج.

## الخرائط والبحث والمسار وGPS

الخرائط موصولة فعليًا في واجهتي المستخدم والكابتن منذ [PR #3](https://github.com/82jj/Transport/pull/3)، وأصبحت تجربة تحديد المواقع تبدأ بالبحث المباشر بعد [PR #4](https://github.com/82jj/Transport/pull/4) و[PR #6](https://github.com/82jj/Transport/pull/6). يمكن كتابة الالتقاء والوجهة بالعربية واختيار نتيجة مباشرة، أو فتح خريطة بدبوس ثابت ومراجعة النقطة ثم تأكيدها مرة واحدة. تحديد الالتقاء تلقائيًا يحتاج إذن الموقع من المتصفح. بعد اختيار النقطتين يظهر المسار وخيارات الخدمة؛ تعديل العنوان يلغي الإحداثية وعرض السعر السابق، وإلغاء الخريطة يحافظ على المسودة.

المسافة للطلبات الجديدة المحددة بنقطتين تُحسب على الخادم من طريق فعلي، مع زمن تقديري وعرض المسار، ولا يطلب هذا التدفق إدخال المسافة يدويًا. يبقى API يقبل المسافة للمسار القديم الذي لا يحتوي إحداثيات؛ الطلبات القديمة بلا نقطتين لا تكتسب خريطة أو تتبعًا تلقائيًا.

| وضع `MAPS_PROVIDER` | ما يعمل | حدود الإعداد |
| --- | --- | --- |
| `osm` (الافتراضي عند غياب المتغير) | Leaflet/OpenStreetMap، بحث عربي من فهرس خاص، وOSRM خاص لحساب الطريق والمسافة والزمن عبر `MAPS_ORIGIN` | اقتراح أقرب نقطة طريق معروفة ضمن 250 م يحتاج مراجعة المستخدم؛ لا يضمن مدخلًا مناسبًا للمركبة. |
| `google-demo` (النسخة التجريبية المنشورة التي جرى التحقق منها) | خرائط Google الحقيقية عبر Maps JavaScript SDK، بحث Places بالعربية، عنوان النقطة عبر Geocoding v4، ومسار Google Routes محسوب على الخادم | يستخدم `GOOGLE_MAPS_BROWSER_KEY` التجريبي العام بحصة محدودة؛ تعرض الواجهات `Google (تجريبي)`. لا يثبت جاهزية حساب Google للإطلاق التجاري. |
| `google` | الربط نفسه مع فصل مفتاح المتصفح عن مفتاح الخادم | يحتاج `GOOGLE_MAPS_BROWSER_KEY` مستقلًا ومقيدًا بالنطاقين وMaps JavaScript API، و`GOOGLE_MAPS_API_KEY` سريًا لخدمات Places API (New) وRoutes API وGeocoding API، مع إعداد الفوترة والحصص. يرفض التطبيق الإعداد الناقص أو المفتاحين المتطابقين. |

أُضيف ربط Google في [PR #8](https://github.com/82jj/Transport/pull/8)، ثم فُعّل الوضع التجريبي في [PR #9](https://github.com/82jj/Transport/pull/9). في Google يُحفظ موضع الدبوس المختار ويُجلب عنوانه؛ هذا ليس ربطًا بـRoads API ولا ضمانًا لاختيار أقرب طريق أو مدخل صالح. فشل المزود أو نفاد الحصة يظهر رسالة، دون انتقال صامت إلى مزود آخر. هندسة Google Routes لا تُحفظ داخل سجل الطلب؛ تُحسب عند عرض الرحلة.

GPS الكابتن موصول للرحلة المسندة الجارية بعد تفعيل المشاركة وإذن المتصفح. تظهر أحدث إحداثية لصاحب الطلب والكابتن المسند والإدارة فقط، وتُحفظ مشفرة دون سجل تحركات، مع فحص وقت القراءة ودقتها وإظهار الموقع المتأخر. هدف المسار هو الالتقاء قبل بدء النقل ثم الوجهة بعده. إيقاف المشاركة أو إنهاء الرحلة أو تسجيل خروج الكابتن يمسح آخر موقع ويوقف المشاركة. التتبع يعمل والمتصفح في المقدمة؛ الاستمرار في الخلفية أو عند قفل الشاشة غير مضمون.

تفاصيل متغيرات التشغيل وسياسة الموقع والمزودين في [docs/live-maps.md](docs/live-maps.md)؛ فقرات الفحص السابق فيه توثق مرحلة OSM قبل تفعيل Google التجريبي.

## التحقق

`npm run check` و`npm test` يفحصان التطبيقات الثلاثة وخدمة API فعليًا عبر HTTP. الاختبارات تشمل منع ملفات الواجهات الأخرى، منع تبديل الواجهة باستعلام URL أو APP_MODE، عزل الجلسات والصلاحيات، مشاركة الطلب بين الواجهات، موافقة الكابتن، قبول واحد للطلب، انتقالات الحالة، وحفظ البيانات بعد إعادة تشغيل API.

CI يبني كل Dockerfile من مجلده فقط. فحص `live-isolation` لا يكتفي بـ SUCCESS في Railway: يقارن HTML وJS وCSS والـmanifest على الروابط العامة مع ملفات commit الحالي بالـSHA-256، ويختبر 404 للمسارات الأجنبية و401 للبيانات المحمية. لا ينشئ بيانات اختبار في الإنتاج. النشر الحي لا يعتبر متحققًا حتى ينجح هذا الفحص على الرأس المنشور.

على `main` عند `d14e39a827a07b76426ce8acdb9509802fef4e9a` نجح [Transport isolation checks رقم 37195183014](https://github.com/82jj/Transport/actions/runs/37195183014) في `test` و`browser` و`live-isolation` و`live-browser` يوم 4 أكتوبر 2026: فحص الصياغة، 26 اختبارًا، بناء المشاريع المعزولة، واختبارات Chromium وWebKit. يغطي التحقق تحسينات الواجهة في [PR #5](https://github.com/82jj/Transport/pull/5)، استمرار البحث في [PR #7](https://github.com/82jj/Transport/pull/7)، تحميل Google أثناء البحث في [PR #10](https://github.com/82jj/Transport/pull/10)، وسياسة الفحص الحي في [PR #11](https://github.com/82jj/Transport/pull/11).

الفحص الحي طابق أصول التطبيقات المنشورة، وأثبت تحميل مربعات Google الحقيقية والبحث العربي واختيار النقطتين واستجابة مسار الطرق والزمن، دون إنشاء حسابات أو طلبات أو كتابة GPS في الإنتاج. اختبارات GPS والصلاحيات وتبديل هدف المسار وتنظيف الموقع نُفذت ببيانات معزولة؛ نجاحها لا يُعد اختبار قيادة على هاتف فعلي. اختبارات Google SDK المعزولة تختبر عقد الربط فقط، أما إثبات العرض الحقيقي فيأتي من الفحص الحي المذكور.

## حدود هذه النسخة

نسخة معاينة وليست تشغيلًا تجاريًا مكتملًا. أسعار الخدمات تجريبية وغير معتمدة للتشغيل، حتى مع حساب المسافة من الطريق. الزمن تقديري بلا زحام حي، والمسارات لسيارات عامة وليست معتمدة لقيود وزن وارتفاع الشاحنات أو الحمولات؛ يجب مراجعة المدخل وإمكان وصول المركبة. لم يُجرَ اختبار قيادة ميداني على هاتف فعلي، ولا ضمان لتتبع الخلفية أو الشاشة المقفلة. ترتيب الإسناد حسب أقرب كابتن يحتاج إكمالًا، ولا تجعل إضافة الخرائط الدفع أو إثبات التسليم الموثق أو التحقق الخارجي من المستندات مكتملًا. الإشعارات الخارجية تحتاج تهيئة مزوديها والتحقق من الإرسال؛ وجود محولات الإرسال وطابور القرارات لا يثبت وصول الإشعار إلى الجهاز. وضع Google التجريبي لا يغني عن إعداد مفاتيح وفوترة وحصص الإنتاج.

لا تعرض الواجهات أرقام كباتن أو تقييمات أو إيرادات أو شكاوى وهمية. جميع الطلبات الحالية موسومة كتجريبية. كلمات مرور الاختبارات مخصصة للبيئة المؤقتة في CI ولا تُستخدم في الإنتاج.

المشروع مستقل عن SMT وعن مشروع توصيل الركاب.
